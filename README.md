# glutes-demo

Демо-копия «Биохакинга ягодиц» для показа без подписки: ОДИН ролик разбора
техники, «Базовые правила» 9:27.
Живёт на https://vladlen00.github.io/glutes-demo/

Чем отличается от боевого репозитория `glutes`:

- гейта нет. Блок `irenaCheckAccess` вырезан целиком, а не закомментирован;
- Supabase нет. Чтение расписания `glutes_schedule` через anon-ключ убрано
  вместе с ключом и множеством разблокированных;
- каталога нет. Все тренировки и весь остальной разбор техники выброшены.
  В файле остаётся РОВНО ОДИН Kinescope ID;
- вкладок нет. Убраны «Прогресс» (трекер объёма и привычек, `storage.js`)
  и «Тренировки». Остался один список из одного ролика;
- `storage.js` и `telegram-web-app.js` не подключаются и не копировались;
- кнопка «← В приложение» заменена на «Что ещё есть» с меткой `?from=demo-glutes`;
- `noindex, nofollow` в шапке.

## Почему каталог обязан уехать целиком

Белый список Kinescope **доменный, а не постраничный**. `vladlen00.github.io`
в нём уже есть, поэтому демо играет без правок в кабинете. Обратная сторона:
любой ID, оставленный в файле на этом домене, заиграет у любого, кто откроет
исходник страницы. Вычистка каталога это не гигиена, это и есть замок.

## Правила для этого репозитория

1. Ровно один Kinescope ID в файле. Проверять при каждой правке:

   grep -o "kinescope.io/embed" index.html | wc -l
   grep -o "id: '[A-Za-z0-9]*'" index.html | wc -l

2. Ни одного обращения к Supabase, ни anon-ключа, ни `glutes_schedule`.
3. Демо НЕ читает и НЕ пишет ключи `irena_*`. Здесь хранилище не используется вовсе.
4. Полная проверка перед публикацией, все счётчики обязаны быть нулями:

   grep -c -i -e verify-access -e verify-app-token -e irena_token -e rest/v1 \
        -e glutes_schedule -e supabase -e storage.js -e GlutesStorage \
        -e localStorage -e WORKOUTS index.html
